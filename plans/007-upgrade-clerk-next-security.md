## Why this matters

`pnpm audit --prod` (run 2026-07-01) reports **critical and high** advisories in
the exact libraries that implement the app's only authorization gate:

- `@clerk/nextjs@6.9.6` — **critical** "Middleware-based route protection
  bypass" (patched `>=6.39.2`) and **high** "authorization bypass when combining
  organization/billing/reverification checks" and "insufficient verification of
  data authenticity" (patched `>=6.23.3`).
- `next@16.0.10` — multiple **high** advisories: "Middleware / Proxy bypass in
  App Router applications" (patched `>=16.2.5`, with a follow-up incomplete-fix
  patched `>=16.2.6`), SSRF via WebSocket upgrades, and several Server-Component
  DoS issues.

The app's entire authenticated surface rides on this middleware —
`src/proxy.ts:3-9` calls `auth.protect()` for `/dashboard(.*)`. A
middleware/proxy bypass therefore directly threatens tenant isolation. These are
the highest-severity, most-reachable issues in the repo.

Bundled tidy-up: `@clerk/types` is pinned to `4.5.0` as a direct dependency
while `@clerk/nextjs` pulls `@clerk/types@4.101.6` transitively (both resolve in
`pnpm-lock.yaml`) — your code types Clerk props against a version ~96 minors
behind what Clerk's runtime uses. Removing or realigning that pin belongs with
this upgrade.
